TrafficLight Open-Source Integration

All paths use the same lifecycle contract. The only question is where the reliable start/finish signal comes from.

Recommended architecture
Local Agent Host Codex / Claude Code / WorkBuddy / Hermes / Tigerose macOS │ ├─ generic CLI process ───────► trafficlight run ─┐ ├─ agent supports MCP ─────────► trafficlight-mcp ─┼─► trafficlight CLI ─► TrafficLight.app └─ host owns run lifecycle ────► official adapter ──┘ State rule: any active run = orange; last successful completion = green; cancellation, failure, or waiting for input = red.
A

Layered integration (recommended)

Publish CLI, supervised run wrapper, MCP proxy, skill, and native adapters. Tigerose connects at its run coordinator.

B

MCP only

Easy to install, but the model must remember lifecycle calls. It cannot guarantee automatic state across every Agent host.

C

Wrapper only

Automatic for command-line Agents, but cannot observe GUI-hosted runs such as Tigerose macOS without an adapter.
